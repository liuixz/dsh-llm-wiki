## 优先级问题

### P0 — 「停用即故障」在 UI 里不存在，而且顶部主动撒谎
位置：`web/panel.js:1435-1436`（chipTone 只把胶囊染红，文本仍「已停用」）、`web/panel.js:744-759`（`applyState()` 只看 run/lock）、`web/panel.js:1495`（直接渲染 `task.nextRun`）。
实测事实：五个任务全部 `Disabled`（Pipeline 上次 10-31 02:50，其余 10-27 20:50，距今 8–12 天）；`Get-ScheduledTaskInfo` 对已停用任务**仍返回 `NextRunTime`**，面板把它渲染成「下次运行 11/09/2026 08:50:50」——等于告诉用户「它明天还会跑」。而 `history.latest`（`plugin/panel/history.mjs:129` 已造出）在 UI 里 grep 得到 **0 命中**。
后果：知识库已 8–12 天没有自动化维护，325 条待清理，右上角却是绿色「● 空闲」+ 每行绿色「成功」。这是主动误导，不是信息缺失。
修法：顶部状态改三态健康驱动（`已停用 · N 天未运行` / `部分停用` / `运行中`）；任务页顶部常驻横幅 + 「全部启用」批量按钮；停用任务的结果列压成灰色「上次成功 · 10/31」，不与绿色并列；停用任务的「下次运行」显示 `不会运行`。
命令：`clarify`

### P1 — 不可逆的「压实」无守卫，且「压实中」永远不出现
位置：`web/panel.js:1348` `var compacting = !!(run && run.command === "compact" && run.running);`、`web/panel.js:1351-1362`。
实测：`plugin/panel/server.mjs` 只产出 `finished`，从不产出 `running`（`:180` 是唯一的 run 快照，字段为 `finished`/`exitCode`/`output`）→ `compacting` **恒为 false**，压实期间按钮不置灰、不显示「压实中…」、可连点；而压实不可逆（`dbWhy` 文案自己写着「压实不可逆」）。同时它与「回填向量」「全量」共用 `is-primary` 蓝色实心，破坏性操作获得与安全操作同等的视觉权重。
修法：改读 `run.finished === false`（或让 server 真正产出 `running`）；加 confirm 并带数字「将永久清除 325 条软删记录，不可撤销」；降级为 `is-danger`。
命令：`harden`

### P2 — 历史页弃用结构化数据，60 条日志原样倾倒
位置：`web/panel.js:1506-1560`（`:1553-1556` 只做 150 字截断，`:1548` 列头为 `stale`/`lint`/`Δ`，`:1558` `kind` 列）。
实测：`plugin/panel/history.mjs:31-41` 的 `parseSummary` 已拆出 `facts`，UI 里 grep `facts` 得 **0 命中**；`kind` 列全部为 `pipeline`（`history.mjs:25` 默认值），是整列零信息。
后果：产品最核心资产（时间序列健康度）被压成几十行 `compact51.5%` / `sync0条` 的重复串；用户读完不知道「比上周差了没有」。
修法：用 `facts` 渲染结构化列并在单元格带涨跌色；删 `kind` 列；加「只看异常」开关；默认折叠到 10 行；趋势卡提到面板首屏。
命令：`distill`

### P2 — `compact` 是死代码，窄容器直接溢出（功能不可用）
位置：`web/panel.js:302-331`（30 行降级样式）、`:650` / `:679`；入口 `lib/client.js:138` `compact: false`、`web/panel.html:22` `compact: false`。全文件 `ResizeObserver` = 0 命中。
实测（420px 截图）：工具栏 6 个按钮被裁到只剩 5 个加半个「压」；`vault` 行右侧「改」按钮被切出视口；表格列溢出。设置页槽位宽度由宿主决定，插件不能假设自己有多宽。而作者已经写好的降级样式（表格退化为「标签:值」+ `data-label::before`）从入口被写死成 false，是死代码。
修法：删 `compact` 布尔，改 `ResizeObserver` 监听自身宽度 <720px 自动加 `is-compact`；窄屏工具栏收进「运行 ▾」下拉。
命令：`layout`

### P3 — 键盘与无障碍路径整体缺失
位置：`aria-` 2 处（`:377` 图标、`:699` 刷新按钮）、`.focus(` **0 次**、`keydown` **0 次**、`aria-live` **0**、`role=` **0**、`scope=` **0**；`banner`（`:725-727`）无 `role="alert"`。
实测：点「改」进入编辑态后焦点不落到输入框；Esc 关不掉编辑态；状态变化不播报；tab 栏无 `aria-selected`；表头无 `scope`；状态唯一编码是颜色（红 `is-bad` / 绿 `is-ok` 像素尺寸相同）。
修法：`renderBody()` 后接焦点恢复；`startEdit` 里 `input.focus()`+`select()`；全局 `Escape` 退出编辑；tab 加 `role="tablist"/"tab"/"aria-selected"`；banner 加 `role="alert"`，成功消息用 `aria-live="polite"`；表头加 `scope="col"`。
命令：`polish`

## Persona 红旗

**Alex（没耐心的老手）**：点「改」后焦点不落输入框，要 Tab 穿越大半页面；Esc 完全无效；历史页 60 行无排序无筛选，找「上次失败」只能肉眼扫；6 个命令无快捷键、无「上次用的就是它」记忆；搜索词跨 tab 不清空（`:713-716` 全局 `state.query`），切页后被自己忘掉的过滤条件困住，提示还是「没有数据」而非「搜索无结果」。

**Jordan（困惑的新手）**：「检查」和「体检」是两个不同动作，但说明只在 `title` 里（`:773`），要 hover 才看得到，5 秒内无法决定点哪个；「压实记忆库」零语境，解释在按钮下方 6 行灰字，视觉上属卡片说明而非按钮警告；「层」表的 `概念 81 / 决策 17` 没有任何解释；「漂移」是自造词，出现时无解释；无 onboard、无空态引导。

**Sam（无障碍）**：Tab 到 tab 栏三个 tab 不会宣告自己是 tab、也不说哪个是当前；顶部「● 空闲」是无 `aria-label` 的纯视觉绿点，屏幕阅读器层级里不存在；启用任务后无任何播报；状态唯一编码是颜色，色觉障碍用户无法区分「已停用」与「成功」；11px 表格文字在 200% 缩放下窄容器直接溢出。

**Riley（压力测试）**：`renderBody()` 每次全量 `textContent=""` 重建，且 1 秒轮询期间会被调用（`:1410`），长列表滚动位置每轮归零；压实按钮看起来可点、点完没反应、其实在跑（P1），是「看似可用实则静默失败」的样板；刷新页面后编辑态全丢，正在填的凭据直接没了；`request()`（`:628-638`）无超时，慢网下界面看着「空闲」。

## 次要观察

- `--lw-fg-4` 在 `:204` 被引用但**从未定义**，滚动条 hover 色静默失效。
- `fmtTime`（`:617-626`）是唯一自造的日期格式化器，从未被调用；`lastRun`/`nextRun` 直接贴 `schtasks` 原串。
- 底部「输出 · compact」卡常驻所有 tab，渲染的是一次**已结束**的历史运行（`finished:true, exitCode:0`），却摆成「当前状态」；`run.output.slice(-400)` 会在 JSON 中间截断。
- 过滤掉全部行时只显示「没有数据」，与「本来就没有数据」不可区分；无「清除搜索」按钮，无命中高亮。
- `say()` 单槽位（`:737-742`），连续两个操作时第二条覆盖第一条，用户只能看到最新一条。
- 配置保存永远报 ok（`:1015`），不说写到哪一层、是否产生漂移；漂移卡与「刚刚那次保存」之间无因果连线。
- 三个蓝色 primary 同屏：工具栏「全量」（`:769`）、「回填向量」（`:1306`）、「压实记忆库」（`:1351`）。Operate 面里 primary 的语义是「这里开始」，给三个等于给零个。
- 页标题「LLM-Wiki 管理」+ 副标题「配置 · 计划任务 · 运行历史」把信息架构写成了菜单名，而不是价值主张（如「知识库健康」）。
- 深色模式靠 `@media (prefers-color-scheme:dark)`（`:55`）而非宿主主题属性，系统配色与 DSH 主题不一致时会串色。
- 任务表行内「改 / 启用」两个按钮宽度不一致，5 行按钮列不对齐。

## 问题

1. 如果「知识库正在腐烂」重要到值得单独立一条产品原则，为什么它在 UI 里的面积是一个 11px 胶囊？是不是因为不知道该怎么表达「腐烂」，所以只好把它降级成一个颜色？
2. 五个任务全停是「故障」，为什么修复入口是「启用」按钮，而不是一个说「停用 12 天，损失是什么，一键恢复」的引导？你在让用户做诊断，还是让他做决定？
3. 历史页已有 60 天时间序列、有 `facts`、有 `latest`，为什么不画成一条线？一条走平的线比 60 行文字有力一万倍——你是在怕图表，还是在怕承认数据已经平了？
4. 「全量 / 检查 / 重建索引 / 同步记忆 / 体检 / 压实记忆库」——如果六个词没法用一个工具提示讲清，为什么它们要同时出现在屏幕上？
5. 一个设置页放了三个蓝色实心按钮。如果明天必须删掉两个，你删哪两个？答不上来，就说明三个都不重要。
6. 凭据卡片是全 UI 唯一处理好了风险的地方。为什么同样的注意力没给到压实？是因为凭据有「只写不读」这条硬约束撑着，而压实没有人替它写一条原则？
7. 全新安装、0 页、0 历史、任务未启用时，用户第一次打开看到什么？是「暂无数据」还是「从这里开始」？描述不出来就说明这个面板只为作者自己的已填满状态设计过。
