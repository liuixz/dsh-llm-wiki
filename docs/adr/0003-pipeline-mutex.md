# 管线运行走后台进程 + 全局互斥锁，面板不等待完成

计划任务和面板按钮可能同时想跑管线，而管线会写 `log.md`、`index.md`、各页 frontmatter——本轮修掉的四处损坏里有两处正是「两个写入者叠在同一个文件上」造成的。

决定：面板点「全量跑」时把管线作为后台子进程启动，立刻返回；管线自己持有 `~/.dsh/llm-wiki/.pipeline.lock`（记录 pid、命令、开始时间），发现锁存在就拒绝并回报「谁在跑」；用户可以选择在锁释放后自动补跑一次。

## Consequences

- 面板要在管线运行期间提供实时日志或轮询，否则用户看不到进展。
- 锁文件是跨进程的，计划任务与面板共用同一把锁，因此 `.cmd` 包装脚本里跑的管线也必须遵守它——这要求锁逻辑放在 `llm-wiki-pipeline.mjs` 内部，而不是面板里。
- 进程被强杀会留下陈旧锁，需要靠 pid 存活检查来判定并清理。

## Considered Options

- **同步等待**：面板会被一次全量跑（本机实测数十秒到数分钟）卡住，DSH 里体验很差。
- **允许并发**：最简单，但会把已经修好的损坏重新引入。
