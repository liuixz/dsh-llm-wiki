# ADR-0006 面板说真话：健康三态、不可逆动作守卫、结构化历史

状态：已采纳（0.13.4）

## 背景

`/impeccable critique` 对 `web/panel.js` 打 **17/40**，最差三项是「系统状态可见性 1 分」「错误预防 1 分」「帮助与文档 1 分」。三条都不是审美问题，而是**面板在骗人**：

1. **顶栏绿灯在五个计划任务全停时依然是绿的。** `applyState()` 只看 `run` 与 `lock`：没在跑、没被锁 → `is-ok`「● 空闲」。而实测五个任务全 `Disabled`，管线最后一次**任务触发**是 2026-10-31，距今 8 天。用户看到的是「一切正常」。
2. **已停用任务照样显示未来的「下次运行」。** `Get-ScheduledTaskInfo` 对 Disabled 任务仍返回 `NextRunTime`，`tasks.mjs` 原样透出，面板于是写着「下次运行 11/09」——而它永远不会跑。
3. **「压实记忆库」点一下就直接执行。** 它删 325 条软删条目 + VACUUM，不可逆，没有任何确认。
4. **`run.running` 这个字段不存在。** `/api/state` 的 run 快照只有 `finished`，`web/panel.js:1348` 却用 `run.running` 判断「压实中」，恒为 false，压实期间按钮不会进 loading 态。

另外 `history.latest` 与 `facts` 在 UI 里 grep **0 命中**：`history.mjs` 已经算出了结构化的 `facts`（`lint`/`sync`/`prune`/`compact` …）和最新一次快照，界面却把整条摘要当 150 字纯文本塞进一格，还给了一列 60 行全是 `pipeline` 的 `kind`。

## 决策

### 1）健康信号用「三态横幅 + 状态胶囊」，而不是改顶栏颜色

顶栏那个胶囊表达的是**这一秒面板自己忙不忙**（有运行在跑 / 被锁 / 空闲），它是准确的。错的是一屏之内只有这一个信号。所以不把它改成健康指示器（那会让「正在跑」这个真信息消失），而是在它下面加一条**独立**的横幅，表达**知识库当前健康不健康**。

判据按「硬 → 软」排序，任一 `bad` 则整体 `bad`，否则有任一原因即 `warn`：

| 判据 | 级别 | 说明 |
|---|---|---|
| 计划任务被停用 | `bad` | 任务停了后面全不会发生。这是「停用即故障」原则（PRODUCT.md） |
| 计划任务未注册 | `warn` | 包装脚本没装 |
| 最新日志距今 ≥ 7 天 | `bad` | |
| 最新日志距今 ≥ 3 天 | `warn` | |
| 最新快照 `lintIssues > 0` | `warn` | |
| 探针命中 < 100% | `warn` | |
| 向量覆盖率 < 100% | `warn` | |

「最新日志距今」的口径必须写清楚：**面板无法逐条区分「任务触发」与「手工运行」**。实测 11-07 有 19 条日志全是手工跑 `--compact`/`--sync` 留下的，任务本身已经停了 8 天。所以这条信号偏保守（手工运行会掩盖停滞），详情里明确写「依据: log.md &lt;日期&gt;」，不假装它是任务触发时间。

### 2）`nextRun` 对停用任务一律为空

在 `plugin/panel/tasks.mjs` 里先把 `enabled` 算成常量（`live.enabled !== false && state !== "Disabled"`），`nextRun` 只在 `enabled` 为真时才透出。任务页对停用行渲染「已停用」而不是时间，并给整行加 `.is-off`（灰化）。

### 3）不可逆动作改为卡片内联二次确认

不用 `window.confirm`：嵌入式 webview 常被宿主拦截，且样式与面板完全脱节。改为点一次把按钮替换成 `.lw-confirm`（`role="alertdialog"`）——一句问句 + 红色填充的「确认清除」+「取消」，`Esc` 可退。压实与清除凭据两处统一用这个模式。

同时修掉 `run.running`：改用 `!run.finished`，与同文件另两处一致。

### 4）历史页吃 `facts`，删掉 `kind` 列

- 日志表列从 `[日期, kind, 摘要]` 改为 `[日期, 指标, 摘要]`。`kind` 列实测 60 行全是 `pipeline`，零信息。
- 「指标」列按 `FACT_ORDER = ["compact","lint","sync","okf","prune"]` 渲染成胶囊组，`lint` 含问题数 > 0 时胶囊转 warn 色。
- 新增「只看异常」开关：有异常的行（lint 问题 > 0 / stale > 0 / prune 非 0）加 `.is-stale` 底色，开关一开只留这些行。当前 60 条里有 5 条。
- 摘要列用 `facts` 之外的余量（`e.rest`），空则退回异常项，不再把整条摘要硬截 150 字。

### 5）`compact` 从死代码改成自适应

`lib/client.js` 与 `web/panel.html` 都把 `compact: false` 写死，于是 30 行 `.is-compact` 降级样式从未生效——420px 宽实测工具栏 6 个按钮被裁到只剩 5 个半，vault 行的「改」按钮被切出视口。

改为三态：`opts.compact` 是布尔就听调用方；未传则用 `ResizeObserver` 观察容器宽度，`< 560px` 自动进紧凑模式。这样降级页、DSH 设置页、窄窗口三种场景各自正确，不需要调用方操心。

### 6）键盘与读屏

- `role="tablist"` / `role="tab"` / `aria-selected`，`th` 加 `scope="col"`，运行栏 `role="group"` + `aria-label`。
- **焦点保持**：`renderBody()` 每次全量重建会把焦点打回 `<body>`，键盘用户点「改」→ 输入 → 保存后不知焦点飞哪去了。做法是给会触发重绘的控件打稳定键 `data-fk`（如 `cfg:vault:edit`），重绘前记住、重绘后找回。
- **`Esc`** 退出编辑态 / 关闭二次确认，与桌面软件惯例一致。
- **命令说明**：六个命令的区别此前只在 `title`（悬停才见，触屏与键盘拿不到）。运行栏加一个「?」开关，展开可见的说明表。

### 7）同屏只留一个主按钮

配置页曾同时出现三个蓝色 `is-primary`（全量 / 回填向量 / 压实记忆库），互相抵消。改为：

- 回填向量：仅 `pct < 100` 时才是主按钮（此前条件是 `keyConfigured`，几乎恒真）
- 压实记忆库：仅 `needCompact` 时才是主按钮（本来就是 disabled 条件）
- 健康横幅的「去任务页」：普通按钮，不抢主色

## 后果

- 面板首屏在五个任务停用时显示红色横幅「知识库正在腐化 / 5 个计划任务已停用」，而不是绿灯。
- 任务页不再出现「已停用 + 下次运行 11/09」这种自相矛盾的行。
- 压实必须两步，`Esc` 可退；错误预防从「点一下就没了」变成「看得见代价再点」。
- 历史页从 60 行纯文本变成可筛的结构化视图，`facts` 终于被消费。
- 窄窗口（< 560px）自动进紧凑模式，工具栏不再被裁。
- 端到端探针 `.probe-e2e-panel.mjs`（假 DOM 真跑 `panel.js`）覆盖 38 项断言，含「点压实不发请求」「Esc 后仍未发请求」「取消后焦点回到该行」。

## 被否的方案

### 否：把顶栏胶囊直接改成健康指示器

「正在运行」是面板最该先说的状态，合并掉会让用户在管线跑着的时候看不出它在跑。两个信号语义不同，必须分开。

### 否：健康横幅做成可关闭的 toast

腐化是持续状态，不是一次性事件。可关闭的提示会被关掉然后永远不再看。

### 否：用 `window.confirm` 做确认

嵌入式 webview 常被宿主拦截（拦了就是静默执行），且无法定制文案与语气。

### 否：历史页保留 `kind` 列

实测 60 行全是同一个值。留一列恒定值不是「保留信息」，是占位置。
